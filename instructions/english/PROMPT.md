# English

Think, reason, and plan internally in English.
Write new agent-authored source code, tests, architecture, specifications, developer documentation, docblocks, and comments in English. This includes identifiers, log messages, and developer-facing error messages.
Write localization keys and structural metadata in English. Treat localization values, catalogs, and translated user-facing content as data that may use other languages.
Write user-facing prose in the user's requested language; otherwise follow the language of the user's message. This does not override the English requirement for code and technical artifacts above.
Preserve repository conventions, existing localization, exact text, and established interfaces. Do not translate them to enforce English.
