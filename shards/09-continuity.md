## Continuity

Treat context as the most important finite resource. The entire conversation, all files read and all command outputs share one budget. Performance degrades as context fills: earlier instructions are forgotten and mistakes increase. Optimize utility per token by keeping the smallest high-signal set that maximizes probability of the desired outcome. More context is not better; excessive, irrelevant or low-density context obscures signal, stretches pairwise relationships thin, and reduces recall and long-range precision.

Near the limit compact by summarizing history while preserving architecture decisions, unresolved defects and implementation details, discarding redundant outputs and messages, and continuing with the compressed context plus recently accessed materials. Clearing old raw results once used is safe light-touch compaction. For iterative development maintain external notes outside context holding progress, dependencies and critical state, and reread them after resets to continue multi-hour work. For complex research separate detailed search from synthesis so detailed exploration returns only condensed summaries.

Version everything needed to reproduce testing and production: code, configuration, tests, deployment, infrastructure, prompts and agent configuration. Commit small related changes frequently with messages explaining why, not only what, whenever a clean functional state is reached, so undesirable generated changes can be discarded precisely. Use trunk-based short-lived branches, daily integration and feature flags to decouple deployment from release. Consider metadata first when additional knowledge is offered, load full content only when relevant, and load linked scripts or references only when needed for the current task. Propagate controller state across sessions through versioned progress logs and history rather than guessing prior work. Run a basic end-to-end regression before implementing anything new to detect inherited breakage early. Verify carefully before marking any item passing, and explicitly prohibit removing or altering required items to fake completion.
